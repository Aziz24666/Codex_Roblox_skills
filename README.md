## Start a Roblox development session

1. Download and extract the V32 release, then open the extracted package root in Codex.
2. Read AGENTS.md and INDEX_V32.md.
3. Initialize session continuity in the actual game project folder:

       python C:\Path\To\roblox-codex-game-studio-kit-v32\v25\tools\v25.py start --root C:\Path\To\YourGame --goal "Build and ship my Roblox game"

4. Run V32 local diagnostics:

       python C:\Path\To\roblox-codex-game-studio-kit-v32\v32\tools\v32.py doctor --root C:\Path\To\YourGame
       python C:\Path\To\roblox-codex-game-studio-kit-v32\v32\tools\v32.py audit --root C:\Path\To\YourGame

## V32 player-safety boundaries

V32 tools operate only on local source and the structured files supplied to them. They do not collect player identities, raw chat, voice content, screenshots, or live reports. Case records accept only opaque references and fixed codes; keep identities and original evidence in authorized Roblox moderation systems.

Custom non-chat text visible to other players must follow Roblox's current server-side TextService filtering guidance. If filtering fails, suppress the submitted text. Prefer native TextChatService for chat, and do not inspect platform-integrated chat contents. Static audit matches are advisory, not proof of runtime filtering.

Moderation decisions must be human-reviewed, consistent with published rules, and appealable. No sanctions are generated by report volume, static findings, or heuristics. High-impact decisions can require a second reviewer. The tools never ban, kick, mute, remove content, or change live settings.

## Earlier safeguards retained

Keep game-critical state authoritative on the server, validate remote arguments, and protect persistence. Use evidence-backed profiling and V30 release dossiers. Keep analytics aggregate and purpose-bound; do not build individual-spender profiles. Keep paid outcomes fixed and disclosed, worthwhile free progression, and the mandatory no-gambling policy.
