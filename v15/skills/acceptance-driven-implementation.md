# Skill: Acceptance-Driven Implementation

Convert feature requests into observable acceptance criteria before coding.

Each criterion must describe an externally verifiable behavior, include relevant success and failure cases, and map to a test or an explicitly documented manual check. Implement the smallest coherent vertical slice. Avoid broad rewrites unless the evidence shows they are necessary.

After implementation, report each criterion independently as PASS, FAIL, BLOCKED, NOT_RUN, or NOT_APPLICABLE. A criterion cannot pass without evidence from an executed check.
