# Roblox playtest feedback thematic analysis

## Establish the coding frame
- Define the topic, stage, sentiment, impact, and source labels before coding begins.
- Write concise definitions and examples for each label; train reviewers on the same rubric.
- Allow a neutral or mixed code. Do not force every response into positive or negative.
- Keep observations distinct from hypotheses about why they occurred.
- Record the build, task, method, and coarse device context only when necessary.

## Code consistently
- Use one study-scoped opaque reference per response; do not copy the original text into the analysis file.
- Assign the narrowest supported topic and an impact level based on observed gameplay consequence.
- Separate a reproducible defect from a preference or feature request.
- Use a second human reviewer for ambiguous, high-impact, or safety-sensitive cases.
- Track disagreement and update the rubric transparently instead of hiding contradictory evidence.

## Synthesize with restraint
- Report counts as counts of coded submissions, not percentages of the player population.
- Suppress small categories and small cohorts using the study's predeclared threshold.
- Keep positive, neutral, mixed, and negative feedback visible in the same summary when counts meet the threshold.
- Do not infer causation, player intent, prevalence, or representativeness from comments alone.
- Treat repeated feedback as a signal for investigation, not automatic proof of a defect or a mandate to change the game.

## Validate interpretations
- Revisit the underlying authorized evidence when a theme is surprising or high impact.
- Check whether the pattern is limited to one build, task, device, language, recruitment path, or reviewer.
- Note missing voices and contradictory observations.
- Present the strongest alternative explanation and the next test that could resolve uncertainty.
